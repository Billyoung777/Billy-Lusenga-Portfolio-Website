02 / INFRASTRUCTURE · CURRENT BUILD

🖨️ Printer Fleet Management System

A planned support application for tracking enterprise printers, toner consumption, usage and maintenance so an IT support team can move from reactive printer incidents toward proactive fleet management.

Evidence-driven documentationPortfolio Project

01 — Objective

Centralise printer inventory and operational information into one interface that makes fleet health and maintenance easier to monitor.

02 — Architecture / Design

Web application → dashboard → PHP application layer → MySQL database → printer/device records. Future integrations can collect status through network/SNMP or manual support updates.

03 — Technologies

  • HTML/CSS/JavaScript
  • PHP
  • MySQL
  • Network printer support
  • TCP/IP
  • Reporting and monitoring

04 — Implementation

  • Define printer inventory fields: hostname/IP, model, site, department, status, toner levels and last service.
  • Design dashboard cards for total printers, online/offline state, low toner and upcoming maintenance.
  • Add CRUD workflows for printer records and maintenance history.
  • Add reporting views for toner usage and recurring faults.

05 — Testing & Evidence

  • Prototype data should be tested with realistic but non-sensitive sample printer records.
  • Validate create/edit/search workflows before adding automated monitoring.
  • Document how printer IPs and consumable information are sourced.

06 — Lessons Learned

  • Separate monitoring data from user-identifying information.
  • Keep an audit trail for maintenance actions.
  • Use role-based access before deploying to a real organisation.

07 — Next Improvements

  • Add automated network polling where appropriate.
  • Add CSV/PDF reporting.
  • Add alerting for low toner, offline devices and overdue maintenance.
