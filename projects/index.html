01 / NETWORKING · DOCUMENTED LAB

🌐 Enterprise Network Lab

A Cisco Packet Tracer enterprise-style lab built to understand network architecture before implementation, then configure VLANs, Layer-3 gateways, DHCP, DNS, wireless connectivity and guest-network isolation.

Evidence-driven documentationPortfolio Project

01 — Objective

Demonstrate the ability to design and troubleshoot a segmented small-enterprise network and explain how the devices and services connect.

02 — Architecture / Design

Internet/ISP → R1-EDGE → FW1 → SW1-CORE (Layer 3) → SW2-F1, SW3-F2 and SW4-F3. VLAN gateways live on SW1-CORE. Access switches connect endpoints, servers, printer and wireless access. VLANs used: 10 Management, 20 Servers, 30 IT-ADMIN, 40 Users, 50 Printers, 60 Corporate Wi-Fi and 70 Guest Wi-Fi.

03 — Technologies

  • Cisco Packet Tracer
  • 802.1Q VLANs
  • Layer-3 switching / SVIs
  • DHCP
  • DNS
  • Wireless AP
  • Extended ACL / guest isolation

04 — Implementation

  • Created VLANs on the switching layer and trunk/access links.
  • Configured SW1-CORE SVIs with 10.10.x.1 gateway addresses.
  • Configured DHCP pools for IT-ADMIN, USERS, CORP-WIFI and GUEST-WIFI.
  • Integrated AP01 with the corporate wireless network and assigned wireless clients to the lab VLANs.
  • Created DNS records on DC01 for dc01.technexus.local, fs01.technexus.local and intranet.technexus.local.
  • Applied and tested a guest isolation ACL intended to block Guest-WiFi access to internal VLANs.

05 — Testing & Evidence

  • DHCP clients received addresses such as IT-ADMIN 10.10.30.100/101 and Users 10.10.40.100–103.
  • Inter-VLAN routing tests returned replies from gateways and internal hosts.
  • PC-IT01 successfully resolved and pinged dc01.technexus.local and fs01.technexus.local after DNS records were corrected.
  • The intranet site was reachable directly at 10.10.20.20; hostname resolution was separately tested.
  • Guest ACL verification showed the ACL entries and hit counts, while Packet Tracer reported the SVI as having no inbound ACL in one verification view. This is retained as a troubleshooting note rather than being presented as fully resolved.

06 — Lessons Learned

  • Packet Tracer's CLI differs by device model; some show commands only worked from privileged EXEC mode.
  • DHCP, routing and DNS can each be working independently, so testing should isolate one layer at a time.
  • ACL verification needs both configuration inspection and actual traffic tests.

07 — Next Improvements

  • Add stronger management controls and device hardening.
  • Add a cleaner evidence screenshot set and final topology diagram.
  • Resolve and document the final guest isolation implementation if the lab is extended.
